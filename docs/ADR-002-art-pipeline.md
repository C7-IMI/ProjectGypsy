# ADR-002 — Art pipeline: one source, engine-neutral exports, validators first

**Status:** Accepted, 2026-10-25 · **Decision owner:** operator · **Reviewer:** Lead
**Scope:** how game art and audio are authored, exported, imported and checked.
**Related:** [TOOL-INVENTORY.md](../TOOL-INVENTORY.md) · [DEFERRED.md](../DEFERRED.md) PG-D10–PG-D12 · [ADR-009](ADR-009-vertical-slice.md) (Phase-1 engine) ·
[ADR-001](ADR-001-engines.md) (engine adapters) · [ADR-003](ADR-003-workstream-architecture.md) (capability bus) ·
[ADR-004](ADR-004-generative-media.md).
**Out of scope:** interface/UI design and art direction — the interface rules are parked in
[ProjectPack-ADDENDUM-Interface.md](../ProjectPack-ADDENDUM-Interface.md) and no game-side standard exists (PG-D4).

## Context
1. **The engine is a per-project choice, not a global one** (ADR-001; Phase 1 chose Godot 4.7.2 PC, ADR-009). An asset that can only exist inside
   one engine is a bet on an undecided decision.
2. **The machine is modest and nearly full.** T600 **4 GB VRAM**, 64 GB RAM, C: 252 GB and D: 52.6 GB free
   (inventory recorded 256 GB), UE 5.8 on D: (PG-D11); large generated intermediates are not affordable.
3. **The tools were verified when installed** — Blender 5.2.3 LTS (headless export verified), Krita 5.3.4.1
   (limited headless scripting), Inkscape 1.4.4, ImageMagick 7.1.2-34, FFmpeg 9.0.2, Material Maker 1.8,
   texconv and glTF-Transform among them; the full list with paths is [TOOL-INVENTORY.md](../TOOL-INVENTORY.md).
   Only open-source tools were newly installed, and the paid gaps are deferred (PG-D12).
4. **The art pipeline itself does not exist.** ADR-003's studio harness and its capability manifests are a
   separate decision, and a Phase 0 skeleton exists under `workstream/`; there is still no `assets/` tree, no art
   generator. The pack-wide check list and records now exist (PG-D1/PG-D2/PG-D5 closed); the art-specific pipeline and
   its checks do not. No art check is claimed here.
5. **Two pack laws decide the shape.** §2.5: one source, one generator, one check; §1.4: a derived artefact
   comes from a script that fails loudly on missing input. Part 5 case 5 is a hand-edited generated file.

## Decision
Author in the source format of each class, generate engine-ready artefacts with one script per class, import
through a profile-driven adapter, and gate every generated artefact with validators and a provenance record.

### D1 — One source of truth per asset class
| Asset class | Source of truth | Authored in | Derived (generated, never hand-edited) |
| --- | --- | --- | --- |
| Vector: icons, marks, patterns, HUD shapes | `.svg` | Inkscape 1.4.4 | PNG at each size, atlases, engine imports |
| Painted 2D art, sprites, layered textures, concepts | `.kra` (`.ora` for interchange) | Krita 5.3.4.1 | flattened PNG, channel maps, engine textures, contact sheets |
| Pixel art, frame animation | chosen editor's native file (Pixelorama `.pxo` / LibreSprite `.aseprite`) — O1 | Pixelorama 1.2.3 / LibreSprite 1.3 | PNG sheets, per-frame PNGs, animation data |
| 3D mesh, rig, animation, bakes | `.blend` | Blender 5.2.3 LTS | glTF/GLB (primary), FBX (secondary), bakes, LODs |
| Hand-authored channel maps | `.png` (8-bit sRGB) and `.exr` (linear, when >8 bits matter) | Krita / GIMP / ImageMagick | channel-packed PNG/TGA/EXR per descriptor; BCn at adapter time |
| Procedural PBR material | Material Maker project file | Material Maker 1.8 | texture set + descriptor (CLI unverified — O6) |
| Music | LMMS project file | LMMS 1.2.2 | mastered WAV 48 kHz, runtime OGG |
| SFX, voice, foley | WAV PCM 48 kHz/24-bit | Audacity 4.0.1 | edited/mastered WAV, runtime OGG, loop points recorded |
| Level and map layout | Tiled `.tmx` or LDtk project | Tiled 1.12.2 / LDtk 1.5.3 | engine tilemap/scene and collision, from the same source |

Sources live under `assets/src/` (LFS); derived files under `assets/export/`, generated by one script per row with a
`--check` mode (§2.5). A hand-edited derived file is a defect; a source-less artefact is an **imported source**.

### D2 — Engine-neutral export: glTF/GLB or FBX + texture channels + descriptor + import profile
- **Geometry/animation:** glTF 2.0 (`.gltf`/`.glb`) primary — open, JSON-inspectable, checkable by the installed glTF
  tooling ([Khronos glTF](https://www.khronos.org/gltf/)). FBX is secondary, only where an adapter needs it (O2).
- **Textures:** PNG/TGA for 8-bit sRGB and masks; EXR for linear data above 8 bits. BCn is applied by the adapter
  via `texconv`; a compressed file is never the master.
- **Descriptor:** every export writes `<asset>.json` beside it, generated from the source: colour space per texture
  and channel; channel packing (separate or ORM/RMA); tiling; mip/compression intent; units (1 unit = 1 m);
  pivot, axes, animation fps/range/loop. A versioned JSON Schema validates it before import.
- **Adapters** read the descriptor and write engine metadata; they never guess and never require a per-engine
  source fork. The only engine-specific human-edited file is the profile under `profiles/`.

| Engine | Adapter output | Profile applies |
| --- | --- | --- |
| Godot 4.7.2 (first target) | `.import` settings, imported scenes | sRGB detection, VRAM compression, mips, glTF scale |
| Unity 6000.6.7f1 | importer `.meta` files | sRGB flag, per-platform compression, scale/axes, material remap; batchmode needs a licence check (inventory) |
| UE 5.8.4 | import script to `.uasset` | sRGB, compression group, LOD; delayed by hardware (PG-D11) |
| Flax 1.13 | glTF import settings | scale/axes, texture slots; experimental |

### D3 — Tool roles, and what each is deliberately not
| Tool | Role | Deliberately not its role |
| --- | --- | --- |
| Blender | 3D source, rig/animation, bake, glTF/FBX export, headless | 2D painting or vector art; not the source for icons or sprites |
| Krita | painting, concept art, layered textures; KRA/ORA source | the batch pipeline — headless scripting is **limited** and no headless batch/export path was verified here; not a validator |
| Inkscape | SVG source, CLI export to PNG sizes | raster texture editing; not final icon resampling by hand |
| GIMP / MeshLab | raster fallback and format bridge; mesh cleanup, decimation, inspection | a second source of truth; authoring or rigging |
| Material Maker | procedural PBR authoring; open-source Substance Designer substitute | hand-painted detail; CLI not yet verified |
| ImageMagick | batch convert, channel pack, contact sheets, pixel diff | painting; colour-managed authoring |
| FFmpeg | audio/video transcode, frame extraction, GIF/MP4 | audio mastering or mixing |
| RenderDoc | GPU frame capture and graphics debugging | asset validation |
| Tiled / LDtk | level and map sources | tile art itself |
| Pixelorama / LibreSprite | pixel art and frame animation sources | 3D or vector work; canonical choice is O1 |
| Audacity / LMMS | audio editing / music source | runtime audio conversion (FFmpeg's job) |
| texconv / texassemble / texdiag | BCn compression, channel assembly, diagnostics | a master format — never ship the compressed file as the source |
| gltfpack / glTF-Transform | optimise and validate glTF | hand-editing a shipped glTF |

### D4 — Validators are a first-class capability
Checks only move mistakes faster if they exist. Each check below is unimplemented; it must be **proven to fail**
on a broken fixture (§1.5) and joins `scripts/check_all.py` (§2.22) — never a second list.

| Check | Compares | Fails when |
| --- | --- | --- |
| Export contract | descriptor against its JSON Schema and every referenced file | schema invalid, missing texture, unknown enum |
| Source freshness | export's recorded source hash and tool versions against the tree | source newer than export; tool changed without re-export |
| Channel and alpha | channels, packing and alpha mode against the descriptor | missing/unexpected channel; unused alpha; unpremultiplied blend |
| Tiling continuity | opposite edge columns/rows of a repeating texture against tolerance | a visible seam beyond the declared tolerance |
| Colour space | declared sRGB/linear against the file's declaration and a known grey patch | double sRGB encode/decode; linear stored as sRGB |
| Power-of-two and mip | dimensions, mip intent, compression against the profile | non-POT where undeclared; mips expected but absent |
| Texel density | texels per metre against a per-class band | a 4K map on a 10 m wall; a 256 map on a hero prop |
| UV integrity | overlap, range, padding, area sign | overlapping shells, UVs outside 0–1, flipped faces, no padding |
| LOD and animation | triangle counts per LOD; fps, range and loop ends | LOD chain non-monotonic/over budget; looping clip's first/last pose differ |
| Contact sheet | generated sheet reviewed by a human, hash recorded | sheet stale, or review not recorded |
| Provenance | the record schema in D5 | record missing or incomplete; licence unknown; AI flag unset |

### D5 — Provenance and licensing
Every generated file carries a record in `records/`: asset id, source path and SHA-256, tool id/version, params/seed,
`human | ai-assisted | ai-generated`, model/version/licence if AI was used, source and output licence, approver and
date. `art.convert` rewrites only tool-owned fields; schema validation fails if a field disappears.

- **Fonts:** the licence file is stored beside the font; embedding and redistribution rights are recorded. A font
  without a licence does not enter the repository.
- **Asset-store packs:** the EULA is stored and redistribution limits recorded. Royalty-free is not sublicensable,
  and a limit on shipping raw source files is recorded as a constraint.
- **AI-generated content:** governed by [ADR-004](ADR-004-generative-media.md). No generated asset enters without
  provenance, and non-commercial model terms (YuE2 weights, MusicGen weights, FLUX.1 [dev]) block commercial
  release until licensed or replaced.
- **Upscalers:** Upscayl 2.15 (AGPL-3.0, [repo](https://github.com/upscayl/upscayl)) and Topaz Photo/Video AI are
  installed (see [TOOL-INVENTORY.md](../TOOL-INVENTORY.md)). Either may run only on a **source or concept** with
  provenance — never on a derived or shipped asset to fake resolution — and is recorded as an AI-assisted step. The
  output's commercial status follows the input licence and the upscaler's model terms, which the operator checks.

### D6 — Proposed repository layout
```text
assets/src/       # sources of truth: .blend .kra .svg .wav, material and pixel projects (LFS)
assets/ref/       # imported sources: vendor packs, fonts, references + licences (LFS)
assets/export/    # GENERATED: glTF/GLB, FBX, textures, descriptors, contact sheets (never hand-edited)
records/          # provenance records, one per generated artefact
profiles/         # per-engine import profiles: godot.json, unity.json, ue.json, flax.json
tools/art/        # art.probe, art.convert, art.validate, blender export/bake scripts
```

None of the layout above exists yet. The docs index (`docs/README.md`) and the relative-links guard
(`scripts/check_all.py`) exist. Art operations register in the ADR-003 capability bus (manifests
`art.blender.export` and `art.texture.validate` exist; the operations are not implemented yet). Binaries use Git LFS.

### D7 — Phased delivery
| Phase | Deliverable | Why this order |
| --- | --- | --- |
| 0 (this change) | This ADR and ADR-004 | a decision before code |
| 1 | `art.probe` (registered as an ADR-003 capability): tool paths/versions/headless modes, engine import capability, GPU and disk limits, scratch roots | later scripts must not assume a path or capability; the inventory is manual and would drift |
| 2 | `art.convert`: Blender headless export + bake, descriptor schema, contract/source-freshness validators, contact sheets, first simple asset | proves the contract end to end; exporting without its check is the failure §2.5 exists to stop |
| 3 | `art.validate`: remaining validators (tiling, channel, alpha, colour, POT/mip, texel density, UV, LOD, animation), fixtures proven red | checks before asset volume |
| 4 | Godot adapter first (only verified headless loop), Unity after its licence check, Flax later, UE deferred (PG-D11) | import correctness needs a neutral contract already checked |
| 5 | Krita automation (after the headless limit), Material Maker CLI (unchecked), Inkscape batch sizes | 2D automation is convenience, not the critical path |

## Consequences
- **Good:** the engine stays replaceable; assets regenerate; licensing is auditable; broken channels or colour space are caught before import.
- **Cost:** every asset needs a source, a generator and a record; glTF does not carry every engine's material
  model, so adapters and profiles are real work; sources and exports both live in the repository (LFS) with C:/D:
  headroom limited (PG-D11); bakes need a scratch root and cleanup.
- **Honest limit of the tools:** Krita's limited headless scripting means some 2D exports may stay manual until
  Phase 5, and a manual step is a drift risk unless its checklist is recorded and checked.

## Alternatives rejected
| Alternative | Why rejected |
| --- | --- |
| Engine-native assets as source (`.uasset`, prefab, `.tscn`) | locks the library to the current engine (ADR-009); binary and unreviewable; cannot switch engine |
| FBX as the only exchange format | closed, heavier to inspect/validate; glTF is open and tooled here; FBX stays a fallback |
| One texture pack for every engine | sRGB, compression and channel conventions differ; the profile exists because one pack cannot be right for all |
| Hand-edited engine metadata (no adapter) | two sources that must agree with no mechanism — the §1.2 failure |
| Defer validators until assets exist | a validator written afterwards blesses whatever the assets are; the contract must be checked from the first export |
| GUI export presets as the pipeline | not reproducible or scriptable, unverifiable per §2.18; the source/generator/check triad needs a command |
| Upscaled output treated as a new source | provenance laundering: resolution creates neither authorship nor licence |

## Open decisions and risks
- **O1** Canonical pixel editor: Pixelorama or LibreSprite. Choose one or the class has two sources.
- **O2** Is FBX permitted at all? It brings Autodesk SDK/licence questions into a Blender export path.
- **O3** Descriptor carriage: sidecar JSON only, or mirrored in glTF `extras`? A mirror is a second copy.
- **O4** First adapter target: **resolved** — Godot 4.7.2, PC (ADR-009); it has the only verified headless/build/capture loop here.
- **O5** Texel-density bands, poly budgets and LOD counts are art-direction decisions — none chosen; no style
  standard exists (PG-D4 covers interfaces, not art, but the operator-decides logic applies).
- **O6** Does Material Maker 1.8 expose a usable export CLI? Unverified; if not, procedural materials stay manual.
- **O7** Are exports committed or built by CI, and who approves an artefact's record — operator or Lead, stored
  where? LFS storage against reproducibility; CI runs the same check list (PG-D2 closed).
- **Risks:** validators that pass on wrong input (mitigate: break it first, §1.5); tool upgrades changing export
  hashes; disk exhaustion on D:; GUI steps drifting from the scripted path; UE5 import unverifiable until PG-D11.
